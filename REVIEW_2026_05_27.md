### Cumplimiento de principios POO (UT1)

En este apartado se valora si el código respeta los principios de encapsulación, herencia y polimorfismo que se trabajaron en la unidad 1, antes de empezar el proyecto. Aquí se ha detectado un punto a corregir.

#### Discriminación por tipo en lugar de polimorfismo (-0,5)

El repositorio mira con `isinstance` qué subclase de `Dispositivo` recibe para decidir cómo guardarla. En UT1 vimos que en POO eso lo debe decidir **la propia subclase** sobreescribiendo el método, no quien la usa.

Incumplimientos detectados (2 ocurrencias en `infrastructure/repositories/edificio_repository_sqlite.py`, método `agregar_dispositivo`):

- `isinstance(dispositivo, Sensor)` para decidir `tipo = "SENSOR"` y `estado = None`.
- `isinstance(dispositivo, Actuador)` para decidir `tipo = "ACTUADOR"` y `estado = 1 if dispositivo.estado else 0`.

**Ejemplo del problema:**

```python
if isinstance(dispositivo, Sensor):
    tipo = "SENSOR"
    estado = None
elif isinstance(dispositivo, Actuador):
    tipo = "ACTUADOR"
    estado = 1 if dispositivo.estado else 0
else:
    raise ValueError("Tipo de dispositivo desconocido.")
```

**Por qué importa en tu proyecto.** Aunque solo hay dos tipos, el patrón es el mismo: si añades un `Termostato` (que sería un tercer subtipo), tienes que volver a este `if/elif`. Y si lo olvidas, el repositorio lanza `ValueError` aunque el código del dominio funcione perfectamente. En POO, el repositorio no debería conocer qué subclases existen.

**Cómo resolverlo.** Que cada subclase declare su tipo y cómo se representa su estado para la BD:

```python
# En domain/entities/sensor.py
class Sensor(Dispositivo):
    TIPO = "SENSOR"
    def estado_para_bd(self):
        return None

# En domain/entities/actuador.py
class Actuador(Dispositivo):
    TIPO = "ACTUADOR"
    def estado_para_bd(self):
        return 1 if self.estado else 0
```

El repositorio queda sin `isinstance`:

```python
def agregar_dispositivo(self, habitacion, dispositivo):
    tipo = dispositivo.TIPO
    estado = dispositivo.estado_para_bd()
    # ... INSERT con tipo y estado
```

Cada subclase nueva solo necesita declarar su `TIPO` y su `estado_para_bd()`, sin tocar el repositorio.
